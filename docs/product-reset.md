# LiteFetch 重设计：范围与设计核对草案

日期：2026-10-27。本文保留本轮人类决策与迁移核对记录，不是实现完成报告。正式技术规格和验收在 [GitHub #29](https://github.com/Coh1e/litefetch/issues/29)，执行状态在任务 #1—#28 维护；不在本文重复维护。

2026-10-28：协作分工改为 DSH 一肩挑，需求、设计、拆票、编码、测试与验收由同一代理完成，pi 及外部调度/独立验收角色退出。下文涉及分工与 pi 的表述按 AGENTS.md 现行规则执行，其余决策记录保留。

## 本轮人类已确认

- 完成已有完整目标，不能把 HTTP 子集或阶段交付当成项目完成。
- 改用 Win32 原生，替换 Qt；保留源码与逆向研究作为迁移输入。
- 人类已确认当前及后续对话使用用户级安装的全局 pi，并复用其全局配置与认证；项目内保留会话和运行产物，不复制全局认证。此决定取代早期“项目内无认证即需重新配置”的前置假设，长期规则见 AGENTS.md。
- Figma 优先参考外观和设计理念；与本地实现或既定需求冲突时，由人类确认。
- 清理过时指令、重复状态和失效入口，保留有价值的源码与历史证据。
- MiniThunder 逆向参考仅限主程序代码，以完整功能清单为边界核对相关行为、关键调用链和异常路径，使新版对应行为可解释、可验证。未知项逐项列明，影响功能或验收的必须解决。浏览器扩展参考 IDM 等现代主流方案，不要求补齐 MiniThunder 旧扩展、旧浏览器环境或其动态对照；此决定替代本轮早先的原版浏览器动态对照要求。
- Win32 版本提供旧 Qt 任务数据库、下载片段、BT/ed2k 恢复数据和设置的显式导入；先备份并校验，导入后保持暂停。不兼容项逐项说明，不自动丢弃旧数据。
- 浏览器扩展安装与本机连接完成后，自动接管仍须用户主动开启，并可随时关闭。未开启或本机未可靠接收时浏览器继续原下载；开启后覆盖重定向、无扩展名附件及必要认证上下文，防止重复下载和交接丢失。
- 正式程序支持便携模式和当前用户模式：前者在用户选定的可写目录存放数据，后者使用 Windows 用户数据目录；切换须显式迁移，不静默改变位置。开发环境的项目本地化约束保持不变。
- 网站、FTP 和代理凭据默认仅本次运行使用；用户明确选择记住后，才使用 Windows 凭据保护能力加密保存。日志、复制链接和导出隐藏密码；便携数据移到其他账户后允许重新认证，不承诺凭据跨账户可解密。
- 正常退出或崩溃后，下次启动恢复任务记录并默认保持暂停，由用户选择继续。已明确启用的计划任务按计划执行；普通任务不因程序启动而自动传输。旧任务导入同样保持暂停。
- BT 和 ed2k 只共享用户已添加任务所拥有的数据，不扫描或共享其他目录；显示上传状态和流量，暂停或停止后终止该任务的网络共享。
- BT 默认下载完成即停止；用户可选择继续做种及分享率、时间限制。此默认值覆盖 Figma 勾选“完成后继续做种”的示例，做种能力完整保留。
- 完成后退出、休眠或关机默认关闭，仅经用户明确设置后启用；执行前显示可取消倒计时。仅所选任务组全部成功完成时触发，存在失败、暂停或等待用户处理的任务时不触发。
- 计划任务仅在 LiteFetch 正在运行时执行，不额外安装后台服务或唤醒电脑。错过的计划在下次启动时提示，由用户决定补跑，不自动覆盖启动后默认暂停的规则。
- 重复添加同一资源时默认定位已有任务，提供继续、查看或明确创建另一份的选择。BT 按种子身份、ed2k 按文件哈希识别；HTTP/FTP 结合来源与目标判断，不只按文件名合并，不擅自删除认证参数。
- 首个正式交付为 Windows 10/11 x64 便携压缩包；浏览器扩展提供配套安装、注册和卸载入口。安装器、自动更新及其他架构后续另定；完整功能、可重复构建和干净环境验收仍属本次交付要求。
- 新添加任务默认立即开始，用户可在添加窗口或设置中关闭；BT 须逐任务确认文件选择后才下载正文。启动恢复和旧数据导入仍保持暂停，不受添加后立即开始设置影响。
- 浏览器登录下载无法可靠交接时，保留浏览器原下载并明确提示原因；仅传递该下载所需且浏览器允许提供的上下文。无法交接的请求不报告接管成功、不取消浏览器下载。
- Figma 未覆盖的浏览器接管、计划任务、低占用模式和托盘操作统一采用菜单或选项对话框入口，主窗口保留 Figma 紧凑布局。具体位置和对话框草案进入规格，新增冲突由人类确认。

以上为 grill-with-docs 的 Q1—Q15 及此前四项冲突决定。人类补充 MiniThunder 仅参考主程序代码后，已确认整体目标基线。详细接口、参数、任务拆分、缺失设计入口与验收规格仍须据源码及设计证据形成，不把已确认的产品方向当成实现或验收完成。
- 本轮恢复的是范围核对、重设计和清理规划；具体实现按 AGENTS.md 执行并自验。

## 完整范围

| 范围 | 迁移与最终验收要求 |
|---|---|
| HTTP(S)/FTP | 真实传输、TLS/认证、资源一致性、续传、HTTP 分段/连接复用/站点限制与回退、FTP REST 与失败恢复 |
| BT/磁力 | 元数据、逐任务文件确认/优先级、发现/连接、校验/恢复、上传、做种策略与持久统计 |
| ed2k/Kad | 同进程发现/排队/传输、完整大文件、上传、入站/LowID、路由维护/持久化与真实互通；不能以基础直连代替完整引擎 |
| 统一任务 | 粘贴/种子/拖放/批量、去重、生命周期、跨引擎调度、全局限速/低占用、错误与恢复 |
| 文件与存储 | 同名策略、空间、SHA-256、分类保存、数据库/检查点、崩溃恢复、凭据保护 |
| Win32 交互 | 中文、DPI、键盘/无障碍、列表/属性/设置、托盘和通知；关闭默认退出 |
| 网络设置 | 系统/自定义代理，各协议覆盖、限制及实际故障行为 |
| 浏览器 | Chrome/Edge/Firefox 自动接管、认证上下文、持久接收确认、失败回退、安装与真实浏览器联测 |
| 计划任务 | 定时开始、时段限速、完成后退出/休眠/关机及取消流程 |
| 逆向 | MiniThunder 仅作为主程序代码参考，复用相关成果并补齐影响新版功能与验收的缺口；不加载原版闭源 DLL、不做迅雷加速/P2SP。旧扩展及旧浏览器动态对照不列验收 |
| 交付 | 项目本地工具与依赖、无 Qt 目标构建/部署、Release、许可证/依赖审计、逐项真实验收 |

## 首批冲突与人类决定

下列决定于 2026-10-27 经人类确认；替代本表中旧方案的对应约束。

| 项目 | Figma | 本地/原范围 | 已确认处理 |
|---|---|---|---|
| 托盘 | 常规设置明确最小化到任务栏、关闭退出，无托盘隐藏范围 | 原范围包含托盘与完成通知 | 保留托盘和完成通知能力；关闭默认退出，不隐式转后台；本轮不新增未确认的默认隐藏策略 |
| 主窗口 | 7 个工具栏命令；6 个默认列；临时查找浮层 | 旧 UI 5 个动作，5 列含类型，常驻筛选输入 | 主窗口采用 Figma；旧功能保留入口，类型作为可选列 |
| 技术标准 | 设计原则标题写 C++20 | CMake 明确 C++23 | 保持 C++23，采用 Win32/Comctl32；不因设计文字降级 |
| 续传回退 | 不可续传时须确认从头下载，保留旧数据直到同意 | 本地 HTTP 续传对 200/204 路径存在清空输出行为 | 统一为确认后重下；确认前保留数据，取消不破坏原检查点与片段 |
| 未画出的完整功能 | 本轮所读页面未给出全部浏览器、计划任务、Kad 和诊断入口 | 完整目标要求包含 | 保留范围；确实缺失时补充符合相同理念的入口方案交人类确认，不视为删除功能的授权 |

Qt 已在 CMake 中连接到 domain、Kad、任务/浏览器等层，迁移包含后端 Qt 依赖替换，不能只改主窗口。
