# BT接入统一任务与原生界面

2026-10-18。本轮实现并通过受控测试，完整项目仍未完成。仍不加载旧迅雷DLL，不使用迅雷加速网络。

## 已接入

- TaskManager接受种子与磁力，BT和HTTP/FTP共用SQLite、优先级和并发名额。BT会话在worker首次需要时懒创建，共享session，不在空窗口启动时启动DHT。
- 本地种子只读一次快照，按内容解析/校验，规范化为完整哈希的磁力身份；原始字节作为BLOB与文件优先级在同一事务提交。不会只存易失的原始文件路径。GUI预览身份与最终快照不符时拒绝接收。
- 数据库schema v3在v1/v2基础上增加file_priorities和torrent_metainfo，迁移在事务中进行。新字段严格检查数量、数值和16MiB缓存界限；当前启动会加载这些缓存，海量任务的懒加载优化尚未完成。
- hybrid的v1/v2身份别名在接收时交叉匹配，已有任务提示并选中；单个GUI会话锁保持一套调度者。
- “打开种子”/Ctrl+O及磁力输入均选择新任务目录，拒绝合并非本任务已有目录。BT取消保留数据；重试先重新校验，移除记录保留下载文件。
- 本地种子可立即选择；磁力先获取元数据和保存resume，等待选择，再开放文件请求。选择先提交数据库才唤醒worker。暂不选择则暂停，程序退出可中断等待，不死锁。
- 原生QTableView模型按需提供数据，隐藏padding行，勾选跳过、优先级0—7、全选/全部取消、数量大小汇总；空选择禁用开始。远程名称按纯文本显示。元数据/选择/校验阶段显示独立状态。

## 异步确认修正

组合测试曾有一次单文件复合断言失败，单独及拆分重跑未稳定复现。核对固定2.1.2源码发现需要收紧判据：save_resume_data(flush_disk_cache)会发起async_release_files后直接生成alert，不能据此认定所有磁盘IO完成。现在先等torrent_paused_alert，再保存并返回；新空目录不重复强制校验，已有目录仍强制校验。

prioritize_files同样需要磁盘往返。现等待file_prio_alert并核对get_file_priorities，避免把之前的异步更新或固定100ms延时当成本次选择已生效的证明；磁盘错误会结束等待。不会用校验/优先级变更前的旧status认定完成。

## 当前证据

- 全套CTest **6/6通过**，38.99秒；BT专测30.80秒，原生选择对话框0.36秒。日志logs/downloader-tests-bt-ui.log及构建目录Testing/Temporary/LastTest.log。
- 真实v2种子：接收后独立连接读取SQLite，确认缓存与选择已提交；删除原始输入文件，部分下载暂停，关闭并重开TaskManager，继续后精确得到所选文件，未产生跳过文件。目标目录使用中文名。
- 真实hybrid磁力：本机做种端在选择前payload上传计数不变；选择提交后完成实际文件传输，跳过文件不存在；v1-only/v2-only别名均指向已有任务，移除记录保留数据。
- 获取磁力元数据后拒绝选择，进入Paused且收到0字节文件内容，无等待死锁。
- 原生对话框真实创建并驱动：无选择不能开始，设置“最高”可开始，返回精确优先级/隐藏padding，取消返回单独的拒绝结果。截图downloader/out/verification/torrent-file-selection.png已查看。
- 部署包含torrent-rasterbar.dll及OpenSSL依赖；精简PATH启动真实窗口成功，Qt插件路径来自部署目录。主窗口截图与JSON为qt-smoke-package.json(.png)。

这些是实际TaskManager/本机协议传输与独立原生对话框测试；没有把它包装为全部主窗口点击、文件对话框和公网下载的完整端到端验收。
