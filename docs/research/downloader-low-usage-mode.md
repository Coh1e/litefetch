# 低占用模式

2026-10-21。在原生“选项”菜单增加可勾选低占用模式，Ctrl+Shift+L切换，不增加主工具栏按钮。bandwidth.json schema1新增可选布尔lowUsage；旧文件缺项按false读取，非布尔拒绝。模式与用户三项原始额度一起原子保存。

低占用的有效预算：HTTP/FTP/ed2k共享下载至多128KiB/s，BT会话下载至多128KiB/s，BT会话上传至多32KiB/s。用户原限额为0（不限速）时取低占用上限，原限额更低则保留更低值。关闭模式恢复原三项设置；编辑原设置时不把临时有效额度回填为原设置。对话框明确提示模式开启时的有效上限，启动状态栏显示低占用状态。保存失败恢复菜单勾选，不执行正常的运行限额更新步骤。

这是固定分组的低占用预设，两个下载组的名义合计至多256KiB/s，不是可配置、动态共享的跨核心总预算：仅一个组有任务时不会自动借用另一组额度。原有正文缓冲突发、协议控制流不计额等边界不变，不是网卡整形，也不具备ed2k上传。默认阈值为本阶段实现选择，后续仍可做可调预设。

验证：download-bandwidth-settings加入两组上限、保留更低值、关闭还原、开关保存不改原额度、旧配置兼容及非布尔类型拒绝，连同限速器测试2/2通过，logs/downloader-low-usage-tests.log。构建和依赖守卫通过，Boost44、无新增库。未修改三种协议的实际传输实现，不重复上轮全部网络测试。
