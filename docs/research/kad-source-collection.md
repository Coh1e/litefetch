# Kad 多报文收集与联合找源

2026-10-20，新增 `downloader/src/kad_discovery.cpp` 并扩展 kad_client.h，复用现有 Qt Core/Network，不新增库或后台进程。

`collectSources` 对指定节点发一次按文件hash/大小的查询，保持同一本地UDP socket接收多报文。每个报文严格匹配远端IP/端口、响应节点ID和文件hash，并经过既有有界标签解析。重复整报文以SHA256指纹识别，源条目按userHash和IP/TCP端口去重。数据报乱序不会导致短页被误当作最终页。

限制：最多6个独特页、300候选源、64个收到的数据报、每报文60KB；共享1–60000ms总期限。第一个有效页之后默认等待100ms静默窗口；独特页重置该窗口，重复报文不重置。没有收到回应则期限结束返回空集合和limitReached，不能声称查无此文件。静默结束返回quietEnd；Kad结果流没有可靠的最终确认，quietEnd仍是启发式，不证明所有结果到齐或UDP无丢包。

`discoverSources` 串联已有按XOR距离的节点查找和上述源集合。总预算默认10秒，前半预算用于最多16次节点查询，之后查询最多4个响应节点，每次默认1秒，总候选源仍不超过300。返回节点/源查询计数、失败查询数和预算耗尽标志。单个节点的格式/网络失败不把其他节点结果抹除。暂时保留直连、回调和加密标记，调用方仍需筛选当前可用传输方式。

真实UDP测试 kad_discovery_test.cpp：

- 第一个数据报是一项短页，20ms后发送另一个独特页再重复前页；必须得到两个源、两个独特页，不能提前结束或重复计数。
- maxPages=1时及时终止并报告预算，不伪装静默正常结束。
- 静默节点在总超时返回空和limitReached。

- 源应答文件身份不匹配时，结果不进入候选集合并记录失败查询。
