# ed2k共享请求预算

2026-10-21。ed2k与HTTP(S)/FTP接入TaskManager同一个BandwidthLimiter。HTTP在正文回调消费，ed2k在发请求前acquire额度，将原先最多3个184320字节范围裁成预算允许的更小范围；不在收到文件后睡眠冒充限速。

acquire返回当前可用的正整数字节而非等待整个大块，防止低速时为了凑齐大块长期闲置远端上传槽；最多积累约100ms额度，0不限速时返回调用者允许的上限。等待每25ms检查停止，设置变更唤醒。发请求前再次检查停止、返回值不能为零/超出上限；范围仍不跨part、不超block、最多3段。设置极低速时远端自身超时仍可能发生，并不保证每个公网客户端持续保留上传槽。

缓存恢复的已验证part不占网络预算；重复请求、坏源重新取数据会重新占额度。服务器/Kad/Hello等控制流和报文开销不计入，未实现ed2k上传。任务适配器传入预算，Kad与服务器两种模式使用同一协调器；直接API不传回调保持旧行为。BT仍使用独立会话额度，完整跨核心合计分配尚未完成。

受控实际TCP测试：37001字节小额度请求最终文件一致，累计额度等于文件大小；恢复9728000字节part后仅请求剩余12345字节且仅计12345。测试对端取消了“未填满3段只能在part末尾”的错误假定，协议本来允许请求少于3段，仍拒绝完全空批次。限速器增加请求预算等待取消和不限速返回上限测试。
