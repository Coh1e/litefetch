# ed2k 服务器找源到最终文件

2026-10-20，新增 `downloader/src/ed2k_download.*`，使用现有 Qt/C++ 同进程模块，不新增依赖或后台进程。

`downloadFromServer` 在工作线程执行：连接明确配置的服务器、登录、查询文件源、转换 High ID 的 IPv4 字节序、逐源连接握手、确认文件/part 状态、排队等待上传许可，生成最多三块的一批请求，连续接收并落盘，最后重新读取整文件验证 ed2k hash 并无覆盖发布。成功后发送 CANCELTRANSFER 释放远端上传槽；文件已成功发布后，释放槽的网络错误不把结果倒退为失败。

默认最多尝试 32 个源（可设置 1–255），每个网络操作有超时。Low ID 明确跳过，不能伪装成可直连源；无文件、连接/协议错误、传输损坏的源允许尝试下一源。目标已存在时不开始下载，发布竞争也不得覆盖。取消使用标准库 stop_token，操作开始前、找源后、换源与每批数据之间检查；阻塞网络操作内尚不能即时取消，延迟受 operationTimeoutMs 限定。发布校验阶段的取消响应仍待改进。

初版协调器仅下载 <= UINT32_MAX 字节的文件；64 位分块编解码虽然存在，真实大文件能力协商尚未完成，所以不默认启用。源位图必须覆盖全部数据 part 才尝试下载；跨源可信 part 复用需要先补 hashset/坏块处理，目前每次换源创建新临时文件，失败源的数据不混入另一源。此限制是当前实现阶段，不是放弃完整多源下载/恢复要求。

请求按 184320 字节最大块长度分批，最后一块截到文件末尾，所有块都截到 9728000 字节 part 边界。进度以实际接收覆盖字节为准。保留可信调用方提供的目标路径，不采用远端文件名作为磁盘路径。

`downloader/tests/ed2k_download_test.cpp` 在同一进程内创建服务器和两个 peer 的真实 TCP 端点，源列表先返回拒绝源再返回完整源，客户端必须按顺序完成找源/握手/文件确认/状态/授槽/多批请求。文件为 9728000+12345 字节，检查跨 part 边界与请求连续性，最终逐字节比较且确认上传槽释放。第二种情况篡改内容，整文件校验必须拒绝发布；验证预先取消和临时文件清理。

构建 `logs/downloader-build-ed2k-download.log` 成功；`logs/ed2k-download-tests.log` 的 9/9 专项测试通过（2.09 秒）。这仍是受控协议对端，不证明公网 aMule/eMule 兼容。
