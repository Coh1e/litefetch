# 浏览器自动接管：专用数据管道与 socket 恢复入口

核查日期：2026-10-20。静态分析，未运行迅雷或修改浏览器配置。承接 browser-context-consumer.md。

## 本轮结论

普通任务的连接上下文已有静态路径通向真正的 `WSASocketW` 调用，并有普通/分块响应的专用数据管道。此前只找到了复制与后台分发，本轮补上了接口偏移、管道选择、socket 工厂查询与恢复入口。仍不等于真实浏览器接管已验收。

输入引擎 SHA-256：`38dd7f676a592bf1810e314e370b28fa4a43e2df3e6a8181447335333d1b0083`。

## 为什么直接搜索字段漏掉消费者

`1007ece0` 构造对象时，把一个接口虚表写在对象 `+0x48`。此前 `1007aad0` 按完整对象保存协议块、缓存、长度和状态到 `+0x5d0/+0x5d4/+0x5d8/+0x5dc`。

`1007a5c0` 经上述接口访问同一对象，因此偏移分别为 `+0x588/+0x58c/+0x590/+0x594`，即各减 `0x48`。其给构造函数传完整对象时也明确使用 `param_1 - 0x12`（DWORD 指针，减0x48字节）。原指令与构造伪代码相互吻合。

直接检索完整对象字段只能找到初始化、保存与析构；不能据此判断上下文未被使用。本轮保留扩大检索结果，包括相同常量出现在无关代码中的噪声，没有把所有命中都归到此对象。

## HTTP 分块标记与管道选择

`10079d90` 解析预读头后调用 `10093bd0`。后者遍历头字段，查 `Transfer-Encoding`，去掉值开头的空格/制表符，再用 `100925a0` 比较 `chunked`。比较辅助函数会先调用 `10092540` 归一化双方，然后做字符串相等比较。此路径是对值的相等判别，不能推断支持任意逗号分隔的编码组合。

状态为返回布尔值加1：识别到 chunked 写2，否则写1；尚未发现完整头时不会由这个分支写入标记。

在存在协议块的分支，`1007a5c0` 释放先前候选管道，并选择：

| 标记 | 构造函数 | 样本中的调试名称 | 预读处理 |
|---|---|---|---|
| 1 | `1009a154` | `dupsock_data_pipe` | `10099840` |
| 其他（含2） | `10098e0f` | `dupsock_chunked_http_data_pipe` | `100975b9` |

两种构造都获得保存的协议块。若预读长度大于零，再调用相应预读处理函数。调用后有释放上下文副本的指令；Ghidra 把部分 delete 标为不返回，导致后续伪代码不完整，不能按这一错误注解解释运行行为。

## 从专用管道到 WSASocketW

构造函数通过 `100bc420(0, protocolInfo)` 建立 socket 实现，再由 `100bc170` 包装。原指令核对了两个构造的实际传参；异常序言让伪代码中的部分参数消失，因此没有只依赖反编译原型。

`100bc420` 在协议块非空时：

1. 对全局网络对象查询 GUID `1036fc2c`。
2. 查询成功则调用所得接口虚表 `+0xb8`，参数为输出接口指针和协议块。
3. 查询无结果或该调用失败时，回退到全局接口 `+0x4c` 的普通 socket 创建路径。这里不能推断回退后请求是否成功恢复，或浏览器是否会获知失败。

工厂身份有以下直接证据：

- `1036fc2c` 与 `10375520` 的16字节相同：`b6a9d38273d5414bb58479da3da5a71f`。
- `10030c6b` 把接口的 this 减4，通过 `10004353` 查询 `10375560` 的接口映射表。
- 表在 `10375584` 的记录是 `{GUID=10375520, offset=4, handler=1}`。
- `10004353` 的比较与 handler=1 分支明确按偏移返回接口并增加引用计数。
- `10030b8d` 构造函数把虚表 `1037543c` 写入对象 `+4`。该表 `+0xb8`（地址 `103754f4`）的指针为 `10034080`。
- 另一张表 `10375e04` 同一槽位也指向 `10034080`，但没有因此声称所有对象都能通过相同 GUID 查询。

`10034080` 的原始指令在 `100340e7` 调用 WS2_32 的 `WSASocketW`，六个参数为：

```text
WSASocketW(AF_INET=2, SOCK_STREAM=1, IPPROTO_TCP=6,
           suppliedProtocolInfo, group=0, flags=1)
```

输出指针/协议块为空，或返回 INVALID_SOCKET 时，走 `0x80070057` 错误返回；前置环境检查不通过时返回 `0x80070005`。成功后把 socket 传给 `1004b7d0` 构造的对象，经过 `10032f40` / `100447a0` 包装，并查询 `1036fb0c` 接口返回给调用方。

这说明样本确有恢复移交 socket 的代码路径，不是只有重新提交 URL 的实现。环境检查、接口可用性和后续传输仍是独立条件。

## 预读内容的处理范围

两种预读处理函数均寻找 `\r\n\r\n`，将头部交给 HTTP 头对象，并把分隔符后已有的正文字节保存到管道缓冲中。

- `10099840` 保存正文长度到 `+0x1e0/+0x1e4`，复制到 `+0x1e8` 指向的缓冲，并调用 `10099823`。
- `100975b9` 保存长度到 `+0x1c0/+0x1c4`，复制正文到内部缓冲，并维护 `+0x1c8/+0x1cc` 字段。
- 未找到完整头时，两条路径各有状态标记；后续继续拼头的行为本轮未完成追踪。

这证明接管时已被浏览器读取的正文并非仅作为日志保留。缓冲与后续 recv 的消费顺序、分块边界、重复/丢失字节及最终落盘一致性仍需验证，不能仅凭复制代码宣称无损。
