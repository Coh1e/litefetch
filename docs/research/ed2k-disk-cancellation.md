# ed2k/Kad 校验与缓存阶段的停止检查

2026-10-20，FileReceiver 和 PartCache 接收统一停止回调，下载协调器将 stop_token 与 TaskManager 原子停止标志合并后传入。仅使用既有 Qt/C++，没有新依赖、监视线程或独立进程。

FileReceiver 在数据接收/重叠比较、part校验、part复制、整文件重新校验和最终发布前检查停止。part/文件哈希与复制循环按64KiB读块检查；取消作为异常离开当前操作，不将数据错误地标成损坏，不清除已经校验的覆盖状态。最终无覆盖重命名前是最后一个可取消点，发布已成功则不因迟到的取消反向删除最终文件。

PartCache 在恢复part/数据块、保存hashset/part、准备发布凭据和恢复最终文件校验时检查停止。QSaveFile 写入后、commit前再检查；中断时临时输出析构撤销，上一份已提交缓存保留。已经成功发布后的确认清理不响应取消，避免破坏完成状态。取消未提交复制/校验不改变此前缓存的可信依据。

`ed2k_disk_cancellation_test.cpp` 使用真实磁盘文件和确定性停止注入，覆盖：

- part哈希中断后覆盖计数不变，再校验通过。
- 输出设备接收首块后设置停止，复制不得继续到整文件，源part仍可校验。
- 缓存commit前停止，旧完整part仍与预期数据相同。
- 恢复首块后停止，部分接收不能标为完成，缓存保留并可在新接收器中完整恢复。
- 最终文件扫描取消时不发布，停止复位后重新验证发布成功。
- 已发布文件的恢复扫描取消后，凭据/文件仍可再次校验恢复。

边界：停止检查发生在IO块之间，不能强行打断内核当前的一次磁盘read/write/flush/commit/rename；慢设备或存储驱动阻塞仍可能延迟。TCP连接建立阶段尚未改善停止响应。完整恢复、原子缓存和发布确认继续保留，不声称任意阶段即时取消或断电持久性已完成。
