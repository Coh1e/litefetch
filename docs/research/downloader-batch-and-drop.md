# 批量输入与原生拖放

2026-10-21。Qt“添加下载”改为多行输入，每行普通链接/磁力链/ed2k/本地种子路径；最多100项、文本总长64Ki字符。提交后先逐项parseRequest，格式无效则不开始本批，按规范化source去重。多项共用一次保存目录选择，普通文件采用原有安全化建议名；BT保留文件选择和新任务目录名步骤。打开种子支持多选。主窗口接收文本及URL列表拖放，本地file URL转换为本地路径；异步投递到相同添加流程，不从拖放事件中直接进入模态文件对话框。没有读取HTML、剪贴板监视、目录扫描或新依赖。

既有TaskManager继续执行跨任务重复检查、队列和持久化；同名/存在目标拒绝覆盖。此批处理不是数据库原子事务：用户取消某个BT选择或某项目标冲突时会跳过该项，已添加任务保留；不同URL同名文件目前提示冲突，不自动重命名。整批撤销、统一BT优先级编辑、冲突预览仍可改善。种子格式验证及ed2k启用检查在各项既有流程进行，不能把前面的链接格式预检称为全部内容验证。

新增download-window Qt事件测试，通过真实QDragEnterEvent/QDropEvent投递验证多行、URL列表、本地带空格路径、空输入、101项和超长文本拒绝；logs/downloader-window-tests.log。不是人工鼠标端到端验收，也未声称批量真实下载已测。新增窗口类可独立验证；构建通过。原有32项完整回归上轮通过，本轮未修改传输核心。

部署包使用独立项目数据目录启动，明确Process.WaitForExit，无额外依赖PATH，退出0，standalone.json确认Windows Qt6.11.2窗口可见、引擎接通并保存截图；证据downloader/out/verification/batch-ui/。首次直接启动命令没有明确等待，无报告时不能据此认定打包失败；后续显式等待验证通过，未修改部署逻辑。

清单第2项的用户入口得到补充，尚不代表完整产品完成。HTTP分段、全局限速/代理、完整ed2k/Kad、托盘通知、计划任务及原版逆向剩余项仍保留，不做迅雷加速网络。
