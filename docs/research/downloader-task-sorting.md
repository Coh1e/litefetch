# 紧凑任务表排序与身份保持

2026-10-21，继续用户指定的Everything式紧凑列表方向。新增TaskTable/TaskTableItem，点击列头可排序，默认名称升序；进度按真实百分比、速度按真实字节/秒排序，不按带单位字符串排序。未知百分比及无速度使用-1，升序时排在已知值前；文本按大小写折叠后的本地化比较。

不能直接给旧表启用排序：旧refresh在固定row上逐列setText，第一列或排序列更新可能立即移动行，后续列会写进另一个任务。现在updateTask先暂停排序并阻止表信号，中间完成所有列，再恢复排序和按任务ID恢复选择；删除所选任务不选择相邻任务。筛选跟随布局变化重新按身份/内容计算，隐藏当前任务会清空选择，避免用户对隐藏记录继续暂停/删除。实际操作仍通过任务ID交给TaskManager，不按排序后行号执行。

真实Qt控件测试：2/10/100数值顺序、速度顺序、同一选中任务50次来回移动但ID不变、每行协议与状态标记不串任务、大小写不敏感来源筛选、排序后筛选仍对准原任务、删除选择后不指向邻居。既有拖放/托盘测试一起连续3次通过，logs/downloader-task-sorting-tests.log；构建通过，无新增依赖。不是人工点击主窗口菜单及任务操作的完整端到端验收。

主程序独立启动复核复用scripts/probe-bandwidth-startup.ps1，普通/低占用/坏配置三种场景均通过，logs/downloader-sorted-ui-startup.log；启动截图仍为空任务列表，填充数据排序由上述真实Qt测试证明。未改变网络核心，因此本轮不重复全部协议测试；上轮全量结果按原日志保留。
