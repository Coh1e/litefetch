# BT 做种停止策略：核心阶段

2026-10-21，TorrentRunOptions新增SeedingPolicy，不改变默认行为或引入依赖。seconds为下载完成后本次连续做种时长，范围0..604800；ratioPercent为累计上传量相对于当前所选文件总大小的百分比，范围0..100000。0禁用该条件，两个都0为完成即停止；两个都启用时先达到任一条件停止。无可分享的所选数据（大小0）直接结束，避免纯比例条件永久等待。

元数据已验收、文件校验不再进行且status.is_finished后开始计时，进度报告Seeding；因此只完成所选文件而非全部文件时也可显示做种阶段。达到限制后走既有pause、flush/checkpoint，再返回Completed；手动停止仍走Cancelled/Paused上层路径。比例使用libtorrent all_time_upload和total_wanted，不把它说成实际下载字节比；累计上传计数可能来自恢复数据，时间在重启或重新进入本次做种阶段后重新计时，不是跨重启累计做种时间。辅助纯计算使用long double避免整数乘法溢出。

核心阶段最初仅提供参数入口；后续应用接入见下节。比例阈值的真实上传互操作、跨重启计数语义、做种与下载并发槽协调仍待验证和完善。

## 任务管理、原生设置与持久化

TaskManager的TorrentRuntimeOptions保存策略；管理线程可修改之后启动任务的策略，schedule在线程启动前复制，工作线程只使用该快照。已运行任务保留原条件，暂停后继续会按新策略重新开始计时。设置不即时终止当前做种任务；需要手动暂停后继续才能切换其策略。

“选项 → BT 做种…”为原生Qt对话框，明确标注累计上传/所选大小百分比、时长按本次连续做种计算、两项均0立即停止及先达到任一条件停止。对话框不占常驻工具栏。策略先原子保存到任务数据目录bt-seeding.json再应用；schema1、最多4096字节、严格整数/范围校验、QSaveFile禁用直接写入回退。损坏配置保留并回退默认，状态栏提示。没有注册表/系统设置或新依赖。

新增配置保存/重读、非法保存不覆盖、分数值拒绝且保留原文件的测试，以及管理器非法设置不改变现值测试；既有真实TaskManager暂停恢复BT用例也带1秒策略启动。设置值影响下一次任务启动，重启恢复设置本身不等于跨重启累计做种时长。

实际Qt启动探针验证3600秒/150%配置进入管理器，以及损坏配置回退0/0；两者均退出0且原配置哈希不变。证据work/seeding-startup/1455ad4ac14743a68c3ed68957568225（startup.json及主窗口截图）。未通过鼠标操作设置对话框保存/取消做完整交互验收。

当前限制：做种仍占用统一下载并发槽，没有单独做种并发配额；完成通知在策略结束、任务变为Completed时发出。已Completed记录重新进入做种及真实比例上传的后续验收见下节。低占用上传吞吐、跨重启统计与长时间做种稳定性未完成验收，完整BT做种范围仍需继续。

## 已完成任务重新校验并做种

TaskManager允许已完成BT在至少启用一个做种条件、目标目录仍存在且没有活动worker时重新排队。HTTP/FTP/ed2k完成记录不受此规则影响，0/0策略不重启已完成BT。继续沿用原任务ID、文件选择和恢复元数据，不新建重复任务；核心按既有目录恢复流程强制校验，缺失/损坏数据可能重新下载，并非禁止下载的纯上传模式。目标路径归属和链接检查保持。

界面复用“继续”动作，选中已完成BT时显示“重新校验并做种”；右键在允许时显示同一入口，提示先启用做种条件并说明缺失数据可能重下。更改策略会通知已完成BT更新操作可用性，先复制ID列表再发信号，避免信号处理修改容器导致迭代失效。重新排队时重置旧阶段，避免直接把历史Seeding状态当成新一次做种进度。

## 真实上传达到比例阈值
