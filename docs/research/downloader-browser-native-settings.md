# 原生浏览器接管设置

日期：2026-10-20。Qt Widgets实现，未安装扩展或写入浏览器注册表。

主窗口工具栏新增“浏览器接管”。原生对话框提供启停开关、保存目录与目录选择按钮，明确说明浏览器连接组件仍未注册。这里是本机设置入口，不是已经完成的一键浏览器安装流程。

## 保存与运行行为

- 默认关闭。启用时目录须为绝对路径，已存在或有已存在的父目录；接受保存后才创建需要的目录。取消不会创建目录或改配置。
- 配置通过QSaveFile写入当前任务目录的browser-bridge.json；下次普通启动会读取，不再要求手工传启动参数。显式开发配置参数仍可覆盖路径。
- 编译时从开发manifest读取公钥，C++独立计算固定扩展origin；测试与Node工具计算结果一致，避免让用户输入扩展ID或编辑JSON。
- 新配置保存成功后才启用新的本机服务；已有服务可就地更新开关与保存目录。
- 关闭只拒绝新的prepare。已保存事务仍可查询、作废与提交；重启读取关闭配置时保留恢复端点。
- 目录已删除时也可关闭捕获并保留旧事务恢复。默认关闭的新设置不创建下载目录或无用端点。
- 保存失败会报错，测试证明已有配置文件仍能读回；目录建立与配置保存不是同一个文件系统事务，保存失败可能留下新建的空目录。

BrowserBridge仍需与Native host配置中的端点相同才能连接。此界面没有复制host配置、导入注册计划或注册浏览器组件；这些安装步骤和错误恢复仍待实现。若用户使用显式开发配置，保存仍写该配置文件，保留其端点和白名单。
