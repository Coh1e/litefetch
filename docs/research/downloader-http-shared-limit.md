# HTTP/FTP 共享下载限速

2026-10-21。统一限速的首个接入阶段，完整跨协议全局限速仍未完成。TaskManager持有一个共享BandwidthLimiter，普通transfer（HTTP/FTP）和HTTP续传均在libcurl正文回调中消耗同一字节预算，再写盘。多个并发任务共用额度；不按任务分别设置相同CURLOPT_MAX_RECV_SPEED_LARGE冒充合计限速。不改变进度数值。

限速器使用steady_clock和互斥锁/条件变量，积累最多约100ms额度（极低速至少1字节），默认0不限速。等待释放锁，每25ms检查取消；setRate重置积分并唤醒等待者。正文到达回调时已进入libcurl/系统缓冲，因此此处是传输正文背压限速，允许有界接收缓冲突发，不是网卡精确整形；协议头、DNS、握手、重定向正文不计入。没有FIFO公平性承诺，不保证每个任务均分。

工具栏“普通下载限速”支持运行中调整KiB/s，明确提示只覆盖HTTP(S)/FTP、仅本次运行，0不限速。没有新增配置文件、库或后台。自定义TransferRunner由调用者负责，不强行插入业务测试/外部自定义核心。

测试：download-bandwidth覆盖阻塞等待、取消及时返回、运行中关闭限速唤醒、非法速率不改变配置。download-batch真实两个128KiB文件在合计128KiB/s预算下完成，要求总耗时至少1.7秒且少于7秒、2个真实HTTP请求、文件逐字节一致；此前无速率时约0.1秒。build初次受Windows min/max宏冲突失败，改用括号限定标准函数后通过；这是编译兼容修正。

剩余必须继续：BT会话下载/上传预算、ed2k分块与上传、跨核心总额度分配、低占用开关、设置持久化、代理及原清单其他功能/逆向。不能把当前按钮写成全协议全局限速完成，不做迅雷加速网络。
