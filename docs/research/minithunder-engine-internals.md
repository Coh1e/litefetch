## 架构：导出层不是直接网络实现

大量导出先取得全局服务对象，再按 16 字节接口标识查询服务，调用虚表方法，最后释放引用。`1000446c` 懒初始化 `DAT_10446c2c`。导出所见 `FUN_10015ac0` 等小 helper 在指针/长度间包装内部字符串视图；不得把它推断成进行编码转换或 URL 解析。

`1001deae` 存在默认的接口到模块名映射，并读取 `riid2dll` 等配置。因此模块名是默认映射证据，不等于本次启动一定从磁盘加载同名 DLL；样本把多个实现编入同一大 DLL，还能注册本地对象。

| 接口数据地址 | 默认模块名 | 相关导出 |
|---|---|---|
| 10370f78 | p2sp_pd.dll | 普通任务优先创建/恢复路径 |
| 1037011c | p2sp.dll | 普通任务 fallback |
| 10373b78 | bt_kernel.dll | BT 与磁力链 |
| 10373a48 | emule_kernel.dll | ed2k/eMule |

`1006ee08` 分配对象并调用 `10071720`；后者有 `CP2spDownload` 类型名和虚表写入，随后前者把对象 `+0x94` 注册为接口 1037011c。这是普通下载与 P2SP 命名实现相连的函数级证据，不只是字符串共存。

## 普通任务创建与恢复

### 1000943f create_new_task；10009617 create_continued_task

两者真实导出均接收 **五组数据指针/长度＋第 11 个输出句柄指针**。过程：

1. 请求 10370f78 接口。新建调用虚表 +0x0c，恢复调用 +0x10。
2. 如果内部返回非负且局部输出句柄非零，将句柄写给调用者并登记。
3. 第一接口不可用、返回负数或没有句柄时，再请求 1037011c；新建调用 +0x14，恢复 +0x18。
4. fallback 接口不存在返回 `0x80004002`，输出句柄清零；fallback 方法返回负数或句柄零时也清零。其余返回内部方法原返回值。

所以其成功判断不是单看“返回值等于 0”，导出内部接受“非负返回＋非零句柄”；主程序上层却按返回 0 判成功，两层判断并不完全一致。导出没有主动调用 start_task。

1037011c 的已确认虚表位于 10378c34（CP2spDownload 对象 +0x94）：+0x14→`10070600`，+0x18→`10072df0`。后者恢复分支明显比新建复杂，执行已有数据/名称的查询后选择不同任务构造器；两者都可能返回 `0x80070057` 或 `0x80004005`。尚未恢复其全部子任务类型、原始服务器/镜像/P2P 调度条件，不能宣称得到完整 HTTP 分段算法。

## 任务句柄与生命周期

创建时输出值随后被直接解引用为带虚表的对象，因此是进程内对象/接口句柄，不是可跨进程保存的顺序任务编号。

- `100063ca`：若查询 helper `1000624a` 未找到句柄，则插入集合/树结构（100061b9）。
- `100063f6`：调用同一查询 helper，返回句柄是否已登记。
- `10006e5c`：若找到则删除登记（10006e14）。

尚未恢复完整容器类型、锁和线程安全保证，但登记/查找/删除链条已成对确认。

| 导出 VA | 观察到的行为 |
|---|---|
| 1000640c start_task | 未登记句柄→-12；否则调用任务虚表 +0x0c。某个任务类型值小于 10000 时还增加全局 user_task_count 并写服务配置 |
| 100064b0 stop_task | 未登记→-12；否则调用虚表 +0x10；对应条件下减少 user_task_count（不减到负数） |
| 10006e80 delete_task | 未登记→-12；否则调用虚表 +0x08（引用释放形态）、移除登记，返回0 |
| 1000a8be query_task_info | 未登记→-12；否则查询接口 1037003c 后调用虚表 +0xbc，复制输出结构，内部非负返回归一为0，负数归一为-1 |

query_task_info 明确复制 0x448 字节输出：起始15个DWORD、0x400字节数组、尾部3个DWORD。**字段名称未恢复，不能直接叫作完整任务状态结构定义**。伪代码还对未恢复输出局部指针报不完整形态，建议下一轮由虚表目标及汇编补证字段。

start/stop 直接转发内部结果；delete/query 会自行归一。因此不能统一推断所有 API 的返回值约定，也不能将 stop 自动等同于“无损暂停”或“关闭连接”。

## BT 与磁力链

`10001855/100018f2` 分别创建/恢复 BT：查询 10373b78；两组字符串视图＋四个不透明参数＋输出句柄，分别调用虚表 +0x14/+0x18；接口不存在返回 `0x80004002`。存在接口时局部句柄先清零，无论内部返回值如何都写给调用方，非零即登记；原内部结果原样返回。

BT 工厂 `1020f78b` 创建 `bt_task_interface`（102120a0）并注册接口。该对象 +0x3c 的虚表为 1038efb4：

| 槽位 | 目标 | 已确认语义 |
|---|---|---|
| +0x14 | 10212ae6 | 新建，调用10212902时首参0 |
| +0x18 | 10212b8a | 恢复，调用10212902时首参1 |
| +0x70 | 10210964 | 磁力解析路径 |
| +0x74 | 10212729 | 磁力任务构造路径 |

虚表 QueryInterface `1021211a` 对比的 1038f070 与导出查询的 10373b78 **二进制16字节完全相同**；1038f050 与磁力扩展接口 10373b98 同样相同，故不是仅凭同一对象邻近地址猜测槽位。原始字节见 interface-byte-evidence.json。

`1000241e parse_magnet_url` 请求 BT 服务及扩展接口，调用 +0x70；内部结果0时还检查产物长度必须为 **20字节** 才复制给调用者，否则返回 `0x80004005`。当前只能证明固定20字节产物，不能据此宣称支持 BT v2/32字节纯哈希。

`10002510 create_magnet_task` 接收三组字符串视图＋输出句柄，调用 +0x74，返回0才写句柄并登记。`10212729` 实际创建磁力任务对象（10222e77），不是单纯把磁力字符串改成种子 URL；解析失败可返回 `0x80070057`，对象创建失败可返回 `0x80004005`。

`100025d0 get_magnet_task_status` 校验句柄，输出参数零时返回 `0x80070057`，否则查询磁力任务接口并转发。**引擎有真实磁力任务实现，但主程序66项绑定表不含磁力接口；不能由引擎证明旧GUI已开放磁力。**

## ed2k/eMule

`10007518 create_new_emule_task2`、`10007717 create_continued_emule_task2` 都是 **五组指针/长度＋第11个输出句柄指针**；入口立刻 `*out=0`。先请求10373a48，再 QueryInterface 10370b94；无接口返回 `0x80004002`。分别转发 +0x8c/+0x90，内部输出非零则登记并返回0，零则返回 `0x80004005`；**内部方法返回值未被导出保留**。

这纠正了主程序包装伪代码只展示十项的假象：真实 ABI 包含输出参数，不可照伪代码写十参数调用。相关补证已回写 minithunder-engine-callpaths.md。

构造器10284a3b标记 CEmuleInterface，写主虚表10393ffc；QueryInterface10284ab2支持10370b94，主虚表+0x8c/+0x90分别指向：

- **1028f827 新建**：检查若干必需长度/数据，失败返回-11；解析/验证失败返回-9；构造底层任务102aefcb时传恢复标志0。
- **1028f9cb 恢复**：相同基本校验外，还检查两个路径/文件相关对象，失败分别返回-14、-25；同一构造器传恢复标志1。

这些是内部返回分支，导出可能将其折叠为通用失败，不能直接用来显示最终用户错误文本。任务路径生成、临时文件校验细节及网络调度没有完整恢复。原主程序恢复失败时还会清理临时文件再新建，见调用路径报告。

## 排除迅雷网络的工程结论

普通下载优先/回退都经过 P2SP 命名服务；任务层还暴露资源策略、CID/GCID、hub、报告和信用接口。**明确不做迅雷加速网络，应在新产品架构中完全不加载这套旧引擎**，采用 libcurl、libtorrent、开源ed2k核心；只借鉴已证实的任务流程。

这不是断言“P2SP模块里的每条代码都专有”或“旧引擎离线时HTTP必不可用”。本轮只证明原本地代码的耦合边界，未验证远端服务可用性，也没有尝试禁开关后联网。
