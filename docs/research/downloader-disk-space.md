# 下载前磁盘空间检查

2026-10-21：已覆盖可恢复 HTTP 下载的已知长度响应。使用 QtCore 的 QStorageInfo 查询暂存文件所在卷对当前用户可用的字节数，无新增依赖。

- 合法 206 响应按总长度减已验证续传偏移检查；200/204 从头接收按完整长度检查。
- 空间明确不足时，在正文写入及旧前缀截断之前返回 TransferError::Disk，提示需要/可用字节及卷路径；原恢复清单和暂存数据保留。
- 从头重试不把旧文件的逻辑长度当作可释放空间，避免稀疏/压缩文件高估实际占用。这一策略较保守，可能要求先释放更多空间。
- 未知长度、卷不可用或查询失败不作空间充足保证，继续依靠实际写入错误处理。预检不预留空间，并发下载或其他程序仍可能耗尽磁盘；恢复元数据的额外空间也未预留。

验证：构建通过；download-resume 测试通过（7.29秒），包含回环 HTTP 超大长度响应在正文前被归类为磁盘错误、有续传前缀时拒绝完整重下且前缀/清单逐字节不变、随后继续下载文件内容准确。日志：logs/downloader-tests-disk-preflight.log。通过声明巨大长度模拟明确不足，没有实际填满磁盘；未验证操作系统实际写入耗尽场景。

## ed2k 同进程下载

新增目标暂存及缓存预检：发布收据恢复仍先执行，不阻止已有完整文件的离线确认；新建接收器之前检查完整目标大小，因为恢复分片需要复制到新的暂存文件。接收每个新分片之前，再检查目标剩余数据量；目标与缓存处于相同已识别卷时，加上当前分片的缓存大小，不同卷分别检查。写入缓存的 QSaveFile 之前再次检查完整分片大小，不把被替换缓存文件的逻辑长度当作可释放容量。

明确不足通过 DiskSpaceError 传播，下载器不会将其当坏来源吞掉重试，任务层映射为磁盘错误并保留原缓存。检查本身只查询空间，不删除旧缓存或创建目标文件。实际写入错误的全面磁盘分类仍需完善。

构建通过，磁盘检查及 ed2k 相关15项测试通过（logs/downloader-tests-ed2k-space.log）；新增测试确认不存在的多层路径可查询父卷，巨大空间需求被拒绝且不创建路径。现有分片恢复、发布、取消、回环下载测试通过。没有通过填满磁盘验证 ed2k 的实际空间不足端到端场景，也没有模拟卷查询失败或跨卷容量竞争。

随后完整回归39/39通过，58.20秒，日志logs/downloader-tests-space-full.log。包括HTTP续传、BT及浏览器桥接的现有测试；这些通过不扩大空间不足场景的验证范围。

## FTP 已知长度检查

通用 curl 接收器在正文首次写盘之前读取 CURLINFO_CONTENT_LENGTH_DOWNLOAD_T；长度已知时查询剩余字节所需空间，明确不足通过磁盘错误返回。文件长度变化时重新检查。空间查询和错误信息处理在不抛异常穿越 C 回调的边界内执行；未知长度继续原写入错误路径。FTP 当前没有持久续传，因此失败后清理随机暂存文件，不发布目标。

构建及 download-transfer 集成测试通过（logs/downloader-tests-ftp-space.log，0.40秒）：本机带认证被动 FTP 返回巨大 SIZE 后发送普通测试数据，客户端在写入正文前报告 Disk、received=0、目标不存在、最终无残留暂存；同组普通FTP、HTTP、重定向、取消、错误和持久任务测试通过。此测试不证明实际填满磁盘时的行为，也不意味着传输网络字节为零；检查位于写盘回调，可能已接收缓冲数据。

## BT 文件选择后的保守预检

元数据身份和路径检查通过、文件选择确定后，在应用下载优先级及解除upload_mode之前检查空间。种子和磁力链共用这个时序，磁力链没有元数据时不猜测大小。以所选非padding文件在线性种子地址中的范围计算需求，扩展到完整分片边界并合并重叠范围，避免重复计算同一分片，同时覆盖未选文件边界可能需要的partfile数据；最后分片截到种子实际总长度。padding及分配方式可能使估算偏大。无新增依赖。

当前不抵扣已有文件的逻辑长度：稀疏/压缩文件的逻辑大小不等于已分配空间。此策略可能在已有完整文件或恢复下载时误报需要额外容量；不能声称已精确计算恢复任务的剩余空间。需要进一步结合实际分配信息和验证状态完善。查询失败和容量竞争的限制同上。

构建及download-disk-space测试通过，新增计算用例包含所选区间分片扩展、同一分片去重、最后短分片、空选择、零长文件、乱序区间及非法范围拒绝（logs/downloader-tests-bt-space-core.log）。download-torrent和download-torrent-ui两项通过，36.28秒（logs/downloader-tests-bt-space.log），覆盖现有本机BT/磁力链、文件选择和恢复场景。没有实际低容量磁盘上的BT拒绝端到端实测，不能把计算测试扩大为该场景已验证。

## HTTP/FTP 运行中重新检查

可恢复HTTP和通用curl接收器均在正文写入路径定期重新查询空间：第一次正文、距离上次检查已写约4MiB或已过1秒时触发。它不是独立定时器，没有新的正文回调便不会查询；查询和下一次写入之间仍有竞争窗口。已知长度按剩余字节检查；未知长度使用64KiB的小额余量，可恢复HTTP同时取当前回调长度的较大值。这是停止明显不足下载的保守措施，不能预测最终大小；极小文件也可能因不足64KiB余量而被提前拒绝。实际写入错误仍是最终保护。

构建及download-transfer通过，新增EOF定界未知长度HTTP精确内容用例。新增8MiB chunked用例初次在4MiB处得到partial-file错误，检查发现本机测试服务在等待一次bytes-written后便继续/关闭，并未保证发送队列排空；修正测试服务循环等待后download-resume通过（8.84秒）。保留失败诊断输出，避免把截断测试源误当空间检查成功。日志downloader-tests-runtime-space-transfer.log、downloader-tests-runtime-space-resume.log。这些测试未模拟磁盘在运行中实际耗尽，不证明该端到端异常场景已验证。

针对修正后的服务继续连续3次download-resume，均通过（8.90/8.85/8.83秒，总26.59秒），日志downloader-tests-runtime-space-repeat.log。

仍需覆盖：BT已有数据/稀疏分配的精确剩余空间、运行中实际耗尽验证，以及并发任务预算协调。ed2k 每个分片前检查只计当前分片缓存，不预留后续全部缓存；其他进程仍可消耗空间。不能将当前实现称为全协议磁盘检查完成。
