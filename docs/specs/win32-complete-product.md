# LiteFetch Win32 完整产品规格草案

2026-10-27。产品目标、四层验收边界及 28 项分票均已获人类确认。正式规格已发布到 [GitHub Issue #29](https://github.com/Coh1e/litefetch/issues/29)，后续技术行为、验收和执行状态以该规格及子任务为准。下文保留发布前草案供追溯，不另行维护第二份执行规格。发布不表示实现或验证完成，尚未启动编码。

## Problem Statement

迁入工程保留了 Qt 实现、历史验证与 MiniThunder 研究，但尚未完成完整产品范围。用户需要一个以紧凑原生列表为中心、统一管理普通链接及 P2P 下载的 Windows 应用，能够可靠接管浏览器下载、恢复任务并明确处理失败，而不是仅替换窗口或交付少数协议的演示版。

## Solution

采用 C++23 / Win32 原生实现，整体移除产品对 Qt 的依赖；外观和理念参考人类提供的 [Figma 设计](https://www.figma.com/design/rUBzBWaWYrVZGMZlqYDCdx/lite-fetch)。完整交付 HTTP(S)/FTP、BT/磁力、同进程 ed2k/Kad、统一任务与存储、浏览器接管和计划任务。复用有证据支持的现有实现与研究，逐项补齐缺口。分阶段实现，但仅全范围实际验收完成或遗留项获人类明确认可才报告完成。

## User Stories

1. 作为下载用户，我希望粘贴链接、打开多个种子、拖放和批量添加，以统一创建任务并看到每项错误。
2. 作为下载用户，我希望同一资源优先定位已有任务，以避免误建重复传输，同时能明确另建一份。
3. 作为下载用户，我希望下载 HTTP/HTTPS 和 FTP 文件，以获得正确内容、认证及明确的错误恢复。
4. 作为下载用户，我希望 HTTP 根据服务器能力使用分段、连接复用和站点限制，并在不支持时可靠回退。
5. 作为下载用户，我希望续传前检查资源与本地片段，不能继续时经确认再重下，以保留已有数据。
6. 作为 FTP 用户，我希望支持被动二进制传输、按需认证、REST 续传及远端变化判断，以可靠恢复任务。
7. 作为 BT 用户，我希望异步取得磁力元数据，并逐任务明确确认文件和优先级后才开始正文传输。
8. 作为 BT 用户，我希望多种子共享一个文件选择管理窗口，并分别保留各任务的选择草稿。
9. 作为 BT 用户，我希望查看文件、连接和追踪器、调整优先级、校验数据并恢复任务。
10. 作为 BT 用户，我希望完成后默认停止，也能选择做种和比例/时间限制，并跨重启保留真实统计。
11. 作为 ed2k 用户，我希望通过服务器和 Kad 发现来源，连接、排队、传输、校验和恢复，包括大文件。
12. 作为 ed2k 用户，我希望具备上传、入站和 LowID 相关能力、路由持久化与诊断，以完成实际网络互通。
13. 作为 P2P 用户，我希望只共享已添加任务的数据，并在暂停/停止后终止该任务共享。
14. 作为下载用户，我希望暂停、继续、停止、重新下载及重试有明确语义，并由引擎确认真实结果。
15. 作为下载用户，我希望全协议统一排队、并发和优先级，并可设置真正的全局上传/下载限制及低占用模式。
16. 作为下载用户，我希望按协议使用系统或自定义代理，并明确看到覆盖范围和失败原因。
17. 作为下载用户，我希望区分删除记录与删除文件，只删除明确归属当前任务的文件，并先停止写入。
18. 作为下载用户，我希望同名文件默认得到保留，并在替换、重下或迁移前明确确认。
19. 作为下载用户，我希望空间不足时保存已有内容，修复位置或空间后再显式继续。
20. 作为下载用户，我希望使用用户提供的 SHA-256 检查内容，并明确区分传输完成和完整性验证。
21. 作为下载用户，我希望按需分类保存文件，并能打开完整文件或实际存在的目录。
22. 作为下载用户，我希望退出或崩溃后恢复任务记录并保持暂停，直到选择继续。
23. 作为旧版本用户，我希望显式导入旧任务、片段、恢复数据和设置，先备份校验，保留所有不兼容项的说明。
24. 作为用户，我希望选择便携或当前用户数据模式，并在切换时显式迁移。
25. 作为认证下载用户，我希望密码默认仅本次使用，选择记住后由 Windows 保护，不泄露到日志、链接复制或导出。
26. 作为浏览器用户，我希望配套安装 Chrome/Edge/Firefox 扩展和本机桥接，再主动开启自动接管。
27. 作为浏览器用户，我希望自动接管覆盖重定向、无扩展名附件和允许提供的认证上下文。
28. 作为浏览器用户，我希望接管失败时继续原浏览器下载，并避免应用与浏览器重复传输或丢失任务。
29. 作为用户，我希望计划开始、时段限速仅在程序运行时执行，错过计划在启动后提示补跑。
30. 作为用户，我希望完成后动作默认关闭，主动设置后只在选定任务组全成功时倒计时执行，并可取消。
31. 作为桌面用户，我希望使用中文、系统控件、DPI 缩放、键盘和无障碍接口，以高效操作紧凑列表。
32. 作为桌面用户，我希望使用托盘和完成通知，同时关闭窗口默认退出，不隐式后台运行。
33. 作为用户，我希望新任务默认开始且可关闭该偏好，恢复和导入仍保持暂停。
34. 作为用户，我希望错误给出真实原因与可执行恢复方式，永久错误不自动反复重试。
35. 作为用户，我希望在干净的 Windows 10/11 x64 环境运行便携 Release 包，并能安装和卸载浏览器配套组件。
36. 作为开发者，我希望可重复构建且附带明确许可证和依赖材料，以维护和分发完整产品。

## Implementation Decisions

- 使用 C++23、Win32/Comctl32 和系统标题栏、菜单、字体、焦点、颜色及滚动条。系统 DPI 和高对比适配优先于设计稿静态像素。产品最终不依赖 Qt；迁移期间的旧实现仅为参考与过渡。
- 复用现有 libcurl、libtorrent、SQLite 与同进程 ed2k/Kad 方向，具体版本和依赖闭包核对后固定；保留最小必要 Boost，不引入全量 Boost、aria2 或 wxWidgets。新的重大技术取舍由人类确认。
- 将任务命令和状态快照作为界面与引擎边界。Win32 界面及浏览器接收层请求操作，调度/持久化层协调，各引擎返回实际确认；界面不伪造成功。
- 主窗口采用 Figma 六个默认列、七个工具栏命令、临时查找浮层、分区状态栏。列表操作依据稳定任务身份，排序、刷新、筛选保持选择、焦点与滚动定位；支持多选并明确可执行任务数量。
- 协议属性页统一为常规、传输、连接；BT 追加文件、追踪器。未知值和已知零不同；详情只显示真实数据。未画出的浏览器、计划、低占用和托盘入口放菜单或选项，具体草案及冲突交人类确认。
- 操作须有引擎确认、持久化提交与可恢复失败。BT 文件确认按任务分别提交，元数据回调不抢焦点、不启动未确认正文。全局限速按跨引擎合计验收。
- 不可续传或资源变化时，确认前保留原数据与检查点。新位置迁移先等待 I/O 静止、验证归属和空间，成功后仍保持暂停。删除文件采用独立确认并报告逐项失败。
- 保持旧数据显式导入边界，先识别版本、备份与验证，再提交兼容转换；不得根据新路径名称猜测旧文件归属或静默销毁无法导入的数据。具体模式迁移随任务设计，不在此预设数据库结构。
- 默认凭据为内存态，明确记住后由 Windows 保护；跨账户便携复制不能解密时重新认证。浏览器上下文仅按单次下载所需及浏览器允许的范围使用，不推导未经确认的持久保存授权。
- 浏览器扩展参考 IDM 等现代主流方案的公开机制和可观察行为，兼顾 Chrome/Edge/Firefox 的现实限制。交接确认绑定实际可靠接收，设计崩溃恢复、重试去重与回退；具体握手和认证覆盖矩阵经研究形成，不臆称参考产品内部实现。
- MiniThunder 仅参考主程序代码，不加载其闭源下载 DLL，不接入迅雷加速/P2SP；不要求复现旧扩展和旧浏览器环境。缺失原始证据时记录缺口，不越界读取其他项目工作区。
- 新任务默认开始；恢复和导入默认暂停；计划仅在程序运行时执行，错过提示补跑。完成动作仅对明确选择的任务组全成功触发，倒计时可取消。后台服务、唤醒电脑不在本次方案中。
- 首次正式交付为 Windows 10/11 x64 便携包及浏览器配套组件安装/注册/卸载入口。开发工具和运行数据保持项目本地；正式程序支持用户数据目录，此产品行为不改变开发环境约束。

## Testing Decisions

以下验收边界已获人类确认。优先复用现有任务管理、传输、恢复、BT、Kad、校验与浏览器桥接测试中的有效场景，不重复照搬 Qt 实现细节。

1. **主要自动化边界：任务命令 → 状态快照与持久化结果 → 实际文件。** 使用真实协议对端或受控服务触发传输、断连、认证、资源变化、存储失败、取消与崩溃；核对文件内容、状态和重启行为。只检查外部可见结果，不依赖内部类布局或函数调用次数。
2. **原生界面边界：真实 Win32 窗口与系统交互。** 验证命令启停、键盘焦点、多选、对话框草稿/提交、DPI/高对比、托盘和通知；按指定 Figma 画板对比外观。空窗口截图不代表下载能力或所有交互通过。
3. **浏览器边界：真实浏览器下载 → 扩展 → 本机接收 → 任务及文件。** Chrome/Edge/Firefox 分别覆盖重定向、附件、认证、禁用、应用离线、连接/进程崩溃和恢复去重；验证回退时原浏览器仍完成下载。旧 MiniThunder 扩展不参与验收。
4. **交付边界：干净 Windows 10/11 x64 环境。** 验证 Release 包启动、实际功能、组件注册/卸载、数据位置、凭据不泄露与动态依赖无 Qt；检查许可证、依赖闭包和可重复构建。明确环境及测试版本。
5. 受控协议测试与真实网络互通分别记录，不能用回环替代公网发现或实际客户端互通；公网偶发失败须保留原因，不掩盖实现缺陷。大文件、资源变化、BT v1/v2/hybrid、ed2k/Kad 长期维护等按独立可观察场景列出证据。
6. 计划和限速使用可控时间与真实流量验证，完成动作通过可验证的系统调用边界测试，并单独验证实际 Windows 行为；明确避免未经授权的真实关机或休眠操作。
7. 每项报告代码和工具版本、命令及退出码、输入与预期/实际结果、证据位置；分别标记本轮运行、静态检查、历史结果、未运行。历史测试数字和模型自述不作为当前通过证明。
8. 每票由 DSH 实现并对照 Standards、Spec 和实际证据自验；单一写入者。总验收覆盖全范围，只补查证据缺口，不重复已证实的相同检查。残留限制须解决或由人类明确认可。

## Out of Scope

- 迅雷加速/P2SP、加载闭源迅雷传输组件、复现旧浏览器扩展环境。
- 远程 RPC、Metalink、插件系统、跨协议混合加速、视频解析、内置资源搜索。
- 首次交付的安装器、自动更新、非 x64 架构和非 Windows 平台。
- 后台服务、程序关闭后运行计划、自动唤醒电脑，以及隐式修改系统网络或共享无关目录。
- 未经人类决定的发布、远端推送或以阶段完成取代全范围交付。
