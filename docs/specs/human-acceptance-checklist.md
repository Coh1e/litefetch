# 人类验收清单

本文件列的是**只能由人在真机上完成**的验收项。自动化已覆盖的部分见
[最终交代](final-report.md) 与 [验证索引](verification-index.md)，那里逐条写了对应的测试名。

每项都给出：怎么做、看到什么算通过、失败时记什么。**没有"看起来正常就算过"的项**。

## 0. 前置

1. 用 `cmd /c test-local.cmd` 跑一遍，确认 `100% tests passed, 0 failed out of 24`；
2. 用 `scripts/package-release.ps1` 生成 `out/package/litefetch-0.1.0/`（5 个文件 / 5.5 MiB）；
3. 把该目录整体复制到一台**没有装过开发工具链**的 Windows 机器上（这就是"干净 Windows"）。

> 第 3 步是 #28 里唯一无法在本会话完成的条件。

## 1. #17 选项对话框（本会话只有代码证据）

1. 启动 `litefetch-win32.exe`，菜单 工具 → 选项；
2. 应弹出"选项"窗口，能看到：下载限速、HTTP 代理、连接超时、并发下载数、ed2k 服务器、时段限速、计划任务、两个复选框、清除密码按钮；
3. 把限速改成 `128`，确定；再打开选项，应看到 `128` 仍在；
4. 关闭程序再启动，再打开选项，**仍应是 `128`**；
5. 在"时段限速"里填一行 `bogus`，确定：**应弹出指出第 1 行格式不正确的提示，对话框不关闭**。

失败时记录：窗口截图、`%LOCALAPPDATA%` 下若有日志、以及第 5 步是否弹窗。

## 2. #18 删除与空间

1. 新建一个下载任务并让它完成；
2. 右键 → 删除任务：文件**应仍在**；
3. 再建一个任务，右键 → 删除任务及文件：文件**应被删除**；
4. 把某个任务的目标目录设到一个**只读**目录（或用另一个账户创建、当前账户无写权限），开始下载：应报权限错误并停止，**不应反复重试**。

第 4 步是本会话无法制造的"真实受阻存储"证据。

## 3. #25 完成动作与计划任务（本会话只有触发点证据）

1. 工具 → 选项 → 把"完成后动作"设为打开文件夹（如界面已暴露该项），下载完成时资源管理器**应打开下载目录**；
2. 设为退出，下载完成时**程序应自行关闭**；
3. 计划任务：在选项里填 `当前分钟+1:s`，停掉所有任务，等到那一分钟：**排队任务应自动开始**；
4. 再填同一分钟等待一分钟：**不应重复触发**。

失败时记录：当时的时间、填写的行、以及任务是否启动。

## 4. #23 浏览器接管（本会话只到协议层）

> **先做这一条，一分钟，能省掉很多猜测**：本会话用 DevTools 协议加载扩展时，扩展的下载事件
> 始终没能驱动交接（详见 `docs/research/browser-handoff-real-chrome.md`）。请人工装一次，看它是否正常：
> 若手动装的时候也交不出去，问题在扩展逻辑；若手动装正常，那只是自动化方式的问题。

1. 确认本机有 Chrome 或 Edge；
2. 在 `chrome://extensions` 打开"开发者模式"，"加载已解压的扩展程序"选择 `browser/` 目录；
3. 注册 native messaging host（**需要先明确授权**）：
   `HKCU\Software\Google\Chrome\NativeMessagingHosts\org.native_downloader.bridge` 指向
   `out/browser-connection/org.native_downloader.bridge.json`（该清单 **UTF-8 无 BOM**）；
4. 启动 LiteFetch，在扩展弹窗里打开开关并允许一个站点；
5. 在该站点点一个下载链接：扩展应把请求交给本机，**本机列表出现一个未开始的任务**；
6. 在扩展弹窗里确认提交：任务进入可调度状态；
7. 关掉 LiteFetch 后再点下载：扩展应收到"无法连接"的错误，**而不是静默失败**。

第 5 步是本会话唯一没跑通的一步，请重点记录它的现象（任务是否出现、扩展弹窗的提示、徽标是否变成 `!`）。

第 3 步的注册键名与清单格式属于需要你确认的部分；扩展 ID 在 `chrome://extensions` 里可见。

## 5. #26 高对比与键盘

1. Windows 设置 → 辅助功能 → 对比度主题，选一个高对比主题；
2. 启动 LiteFetch：**列表、工具栏、状态栏文字应仍然可读**，不出现黑底黑字；
3. 只用键盘走一遍：`Ctrl+N` 新建 → `Tab` 在对话框内移动 → `Enter` 确定 → 列表中 `Ctrl+A` 全选 → `F5` 刷新 → `F2` 打开属性 → `Esc` 关闭 → `Del` 删除；
4. 每一步都应生效，且焦点不会丢失。

失败时记录：主题名、截图、以及断在第几步。

## 6. #34 托盘与通知

> 本会话的 `ui-window` 打印 `notification area unavailable in this session`，所以这一节只能在有通知区的真实桌面完成。

1. 在正常桌面启动 `litefetch-win32.exe`（Explorer/通知区可用）；
2. 通知区应出现 LiteFetch 图标（悬停提示包含 `LiteFetch` 即可；任务数不要求实时刷新）；
3. 右键图标：菜单应有“显示主窗口”和“退出”；点“显示主窗口”应恢复窗口；
4. 最小化窗口，双击托盘图标：窗口应恢复；
5. 新建一个小 HTTP 下载并完成：应出现“下载完成”气球，标题是文件名；
6. 关闭主窗口：进程应退出（任务管理器里没有 `litefetch-win32.exe`），托盘图标应立即消失，不能留下点不开的 ghost 图标。

失败时记录：右键菜单截图、气球截图、关闭后托盘区截图、Windows 版本。

## 7. #28 干净 Windows 交付

1. 把 `litefetch-0.1.0` 目录复制到干净机器；
2. 双击 `litefetch-win32.exe`：应出现"未知发布者"提示（**未签名程序的正常行为**，本会话无证书）；
3. 确认后应正常启动，能新建一个 HTTP 下载并完成；
4. 关闭后重新启动，任务列表与设置**应保持**；
5. 记录：Windows 版本、是否首次运行、有没有额外提示。
