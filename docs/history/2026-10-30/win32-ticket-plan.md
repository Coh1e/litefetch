日期：2026-10-27。规格、四层验收及本拆分已获人类确认。已发布 [父规格 #29](https://github.com/Coh1e/litefetch/issues/29) 和任务 #1—#28；本次本地计划号 01—28 恰与 Issue 编号一致，后续以真实 Issue 为准，不依赖此巧合。以下保留批准时的拆分供追溯，执行状态在 GitHub 维护。尚未启动编码。

关联采用父规格清单及任务正文 Part of / Blocked by；当前 CLI 和连接器没有原生子任务/依赖写入入口，不声称已创建 GitHub 原生关系。

每票由 DSH 在同一上下文内实现并自验，同一时间一个写入者。每票包含实际差异、工具版本、命令退出码与证据。以下复用已有实现；“交付”是验收目标，不表示必须重写已验证能力。若探索发现一票无法在单上下文验收，先说明事实并调整拆分，不降低范围。

## 迁移方式

Qt 涉及多层，采用扩展—迁移—收缩：先引入不依赖 Qt 的任务命令/快照边界及最小 Win32 真实下载链，再逐协议迁移，最后移除 Qt 与过渡入口。禁止只建立新界面后仍把 Qt 后端当最终实现；每票明确新路径是否仍链接 Qt。旧路径保留供对照，不以旧二进制为新版验收。

## 分票与验收

1. **项目本地执行与证据准备**。阻塞：无。
   - 交付：核实项目本地构建前提、工具链版本、项目本地写入和持久会话可用性。缺依赖或配置时记录真实阻塞，不使用其他项目配置。
   - 验收：工具链版本、构建前提和可用历史证据有明确清单；帮助命令成功不能替代真实构建与验收闭环。

2. **任务命令与快照边界的最小验证**。阻塞：01。
   - 交付：为新程序提供无 Qt 的任务身份、命令、快照和持久化边界；在可运行受控下载场景中证明命令到状态和文件的闭环，旧路径保持可对照。
   - 验收：任务身份稳定，实际结果驱动状态，存储失败不报告提交成功；构建和数据格式变更明确，不做无行为验证的全工程机械替换。

3. **Win32 新建 HTTP 下载与真实列表**。阻塞：02。
   - 交付：系统窗口、菜单、七个工具栏动作、六默认列和状态栏；创建 HTTP 任务到真实文件完成，基础动作依据真实能力启停。
   - 验收：新路径不依赖 Qt；窗口关闭有序退出；对照 Figma 主画板，不能用假任务或进度替代下载。

4. **列表、批量入口与基本任务操作**。阻塞：03。
   - 交付：临时查找、多选、数值排序、列设置/持久化、拖放与批量结果、去重定位，以及停止/记录删除/文件与目录打开。
   - 验收：筛选不影响后台调度，操作不误作用于隐藏选择；各行验证与失败可追踪，文件打开按实际完整性和存在性判断。协议特有去重随对应协议票补验。

5. **HTTP 暂停、续传和崩溃恢复**。阻塞：03。
   - 交付：HTTP 检查点、正常退出与强制终止恢复、资源变化与确认重下流程。
   - 验收：重启默认暂停；有效续传文件逐字节一致；200/不支持 Range/变更资源等路径未经同意不清空旧数据，取消确认保留片段。

6. **HTTPS 与站点认证**。阻塞：05。
   - 交付：TLS 成功/失败、重定向认证边界和按需凭据输入，在 Win32 中提供真实错误与恢复。
   - 验收：不关闭证书验证，不向不当重定向目标传递凭据；日志/复制链接脱敏。本票仅内存凭据，记住功能由 21 提供。

7. **HTTP 分段、连接复用与站点上限**。阻塞：05。
   - 交付：自适应分段、可验证连接预算及非 Range 回退。
   - 验收：慢连接、限流、截断、取消、重试和资源变化下结果一致；不支持分段时可靠回退，不绕过确认重下约定。

8. **FTP 下载、认证和续传恢复**。阻塞：05。

   - 验收：REST 成功、缺失/拒绝、远端变化和 421/425/426/530/550 分类恢复；保留旧片段直到确认，错误不误标完成。

9. **BT/磁力真实下载与文件确认**。阻塞：03。

   - 验收：任务之间草稿隔离，异步元数据不抢焦点；未确认不传正文；v1/v2/hybrid 身份去重和真实传输有证据。

10. **BT 属性、文件优先级与追踪器**。阻塞：09。
